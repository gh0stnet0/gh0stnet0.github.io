Un gestor de paquetes para una DSi que no trae nada

DSLinux sin MMU, 4 MB de RAM y un BusyBox sin wget, curl ni tar. Vanapt instala software usando solo lo que trae el shell.

2026-10-31 · proyecto Vanapt, NodeSpectre

Un paquete llega así, línea a línea:

VPK1 hola.sh 3 token
T #!/bin/sh
T echo hola desde la DSi
E

El punto de partida

Consola
Nintendo DSi, ejecutando en modo DS
Sistema
DSLinux (uClinux 2.6), sin MMU
CPU
ARM9 a 67 MHz en modo DS
RAM visible
4 MB de 16 MB físicos
Shell
BusyBox ash, sin utilidades externas
Red
Sin driver conocido para el Wi-Fi de la DSi

La idea

El paquete se convierte en texto plano en el servidor y la consola lo lee línea a línea, sin descargar nada con herramientas externas. Dos builtins de ash hacen el trabajo: read para recibir y printf para escribir.

Como printf entiende escapes octales en el formato, puede reconstruir cualquier fichero binario, incluidos los bytes nulos, sin cat, dd ni base64:

printf '\177\105\114\106' >> fichero

Esto resuelve el límite de read, que no admite NUL: el binario viaja codificado en texto y se reconstruye al escribirlo.

Formato VPK1

Una instrucción por línea. La primera línea es la cabecera con el nombre, el número de líneas y un token compartido.

  • T texto: línea de texto, para scripts.
  • B \177\105...: bytes en octal, para binarios.
  • E: fin del paquete.

No hay eval en ninguna parte. El instalador valida cada línea con una lista blanca de caracteres antes de escribirla y no ejecuta nada: lanzar el script instalado es un paso manual.

El instalador

vanapt-install, versión resumida

#!/bin/sh
# VANAPT_TOKEN=secreto sh vanapt-install < paquete.vpk
DIR=${VPK_DIR:-/tmp/vanapt}
[ -d "$DIR" ] || mkdir -p "$DIR" || exit 1

IFS= read -r magic name nlines tok || exit 1
[ "$magic" = VPK1 ] && [ -n "$tok" ] && [ "$tok" = "$VANAPT_TOKEN" ] || exit 1
case "$name" in ""|*[!A-Za-z0-9._-]*) exit 1;; esac

dst="$DIR/$name"; : > "$dst"; n=0
fail() { echo "linea $n: $1"; : > "$dst"; exit 1; }

while IFS= read -r l; do
    n=$((n+1))
    kind=${l%% *}; data=${l#* }; [ "$l" = "$kind" ] && data=""
    case "$kind" in
        T) printf '%s\n' "$data" >> "$dst" ;;
        B) case "$data" in *[!0-7\\]*) fail "B invalida";; esac
           printf "$data" >> "$dst" ;;
        E) break ;;
        *) fail "tipo desconocido" ;;
    esac
done
[ "$n" -eq "$nlines" ] || fail "truncado"

printf "$data" es seguro porque $data solo puede contener dígitos del 0 al 7 y barras invertidas. Sin % no hay forma de colar otros formatos.

Lo que condiciona el diseño

  • Sin MMU. No hay fork real, así que se evitan subshells y pipelines largas.
  • Binarios bFLT, no ELF. Y para ejecutarlos hace falta chmod. Sin él, solo se pueden usar scripts.
  • RAM. Todo lo que se escribe en /tmp consume esos 4 MB, así que los paquetes son de unos cientos de KB como mucho.
  • Transporte. Un fichero en la SD es el camino principal. Con nc y red, el mismo flujo puede llegar por TCP.
  • Seguridad. El token viaja en claro: sirve contra errores, no contra alguien que escuche. El servidor debe quedarse en LAN o detrás de una VPN.
